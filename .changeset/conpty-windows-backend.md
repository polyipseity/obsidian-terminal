Windows integrated terminals run on a ConPTY backend by default. A standard-library Python host drives the Windows pseudoconsole through ctypes, so full-screen programs (Claude Code, Gemini CLI, opencode, editors) draw and resize correctly instead of leaving stale or duplicated rows after a pane drag. The host starts the shell inside a kill-on-close job object, reports its real exit code, and supports Win32 input mode so `cmd` and PowerShell keep full key fidelity; `cmd`, PowerShell, `wsl.exe`, and Git Bash all take the same path. A new **Windows terminal backend** profile setting chooses between ConPTY and ConHost. **Breaking:** the "Shell pipes" backend and the "Use Windows 'conhost.exe'" setting are removed, and on upgrade every Windows integrated profile moves to ConPTY once when Python 3.9 or newer is found; without Python, profiles stay on ConHost and the settings page says why. Pick ConHost in the profile editor to keep the old behavior; that choice is never changed again. ConHost itself changes in four ways: resizes apply on a 0.1 s throttle, output is sliced and flow-controlled, a missing Python or missing resizer packages open the terminal without its resizer instead of crashing it, and the resizer shuts down quietly. Exit codes 9009, 251, and 0xC0000142 get their own notices. Fixes [GH#104](https://github.com/polyipseity/obsidian-terminal/issues/104); addresses the resize corruption in [GH#145](https://github.com/polyipseity/obsidian-terminal/issues/145) and [GH#168](https://github.com/polyipseity/obsidian-terminal/issues/168), and [GH#142](https://github.com/polyipseity/obsidian-terminal/issues/142).
